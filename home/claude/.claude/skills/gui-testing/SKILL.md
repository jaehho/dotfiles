# GUI testing without taking the screen

- **Hidden Hyprland workspace:** every project's harness parks its windows on `special:claude`, never a workspace of its own. Add a named rule through `hyprctl eval`: `hl.window_rule({ name = "<project>-test", match = { class = "^<app id>$" }, workspace = "special:claude silent", no_initial_focus = true, render_unfocused = true })`. A special workspace is never shown, the bar hides this one, and the workspace packer skips it; the window still renders and takes `hl.dsp.send_shortcut` keys (checked with asst's `scripts/dev`, 2026-11-19). Capture inside the app; grim cannot see hidden workspaces. A rule cannot be removed until Hyprland reloads its config, so name it and a rerun replaces it; kill only the test instance afterward.
- **Isolate data:** a private D-Bus can still activate installed user services with real data. A plain `dbus-run-session` searches `/usr/share/dbus-1/services` whatever `XDG_DATA_DIRS` says, so run it with `--config-file` naming one empty `<servicedir>` (asst's `scripts/dev` writes such a config), and set isolated XDG and config paths. Track child processes as well as launchers. For notifications, keep the IDs `Notify` returns; never clean up by count or position. Restarting the bar clears its notification list.
- **Generic app ids can't be hidden:** a window whose class is `GTK Application` (a bare `Gtk.Application`, as in steno's test stubs) matches no safe rule, so a hidden-workspace rule would also catch the real app. Don't present it on the live display at all: run it on Broadway with `env -u WAYLAND_DISPLAY -u DISPLAY`, so a mistake cannot reach the compositor and take focus.
- **GTK4 Broadway:** `gtk4-broadwayd :N`, then `GDK_BACKEND=broadway BROADWAY_DISPLAY=:N`; the HTTP port is `8080 + N`. Keep its runtime dir short: socket paths over 108 bytes are cut without an error. Wayland/layer-shell apps need an isolated test adaptation. Set an explicit browser viewport; leave a short gap between pointer motion and a press.
- **Headless Chrome:** `google-chrome-stable --headless=new --remote-debugging-pipe` speaks CDP on fds 3/4, NUL-framed. Move pipe ends above 4 before mapping them. An open `confirm()` blocks input until answered. For a script, `--remote-debugging-port=<port> --user-data-dir=<scratch>` and node's global `WebSocket` work too: `Runtime.evaluate` with `awaitPromise`, `Emulation.setDeviceMetricsOverride` (400 px for a phone), `Emulation.setEmulatedMedia` for light and dark, `Page.captureScreenshot`. Stop it by PID, or `pgrep -f '[r]emote-debugging-port=<port>'`.
- **Headless Firefox:** `firefox-developer-edition --headless --marionette`; top-level page `let`s need an injected `<script>`. A plain `--screenshot` may fire before async rendering.
- **Web layout:** don't pass `--hide-scrollbars` for layout checks. Chrome on Linux has classic scrollbars that take width, so an `overflow: auto` box near its content width breaks only when one shows (attune's check rail clipped a column that way). Check the page (`documentElement.scrollWidth > clientWidth`) and every scrolling container while it overflows; a grid column needs `minmax(0, 1fr)` or a wide table stretches the page.
- **Quickshell:** offscreen rendering skips shader items; the `quickshell` skill has a GPU capture that takes no focus.
- **Layout bugs:** measure rendered bounds through the ancestor chain and inspect the installed theme's cascade (generic classes, toolkit defaults). Check rest, hover, and focus separately. Look at the captured image before reporting.
