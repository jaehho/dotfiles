# ome

The owner's always-on assistant on wonlab: a web app in Firefox (phone and desktop) as its only interface, with Web Push for notifications, jobs that wake a model only when a gate script says so, and memory as markdown in git. It took over OpenClaw's jobs on 2026-11-23; OpenClaw is kept on wonlab in Docker with no jobs, only to compare its UI; ome's Apps list starts and stops it (wonlab skill). Decisions are this repo's `decision` issues; the design is in ~/projects/notes/ome-options.md (section C and the staged plan).

- Runs on wonlab as `jaeho`, a systemd user service, from `~/ome`, which only `deploy/wonlab/deploy.sh` writes. Development happens on wonlab in `~/projects/ome`, in the Claude Code session the owner attaches to (a tmux session, or Remote Control); the laptop keeps no checkout. Root work (services, Caddy blocks, secrets) is a staged script the owner runs.
- Power (ome#16, which replaced #12's no-Bash rule): chat runs with full permissions, Bash and every tool with no checks; jobs run in Claude Code's auto mode, and an action it blocks becomes an approval card the owner can Allow. Both reach Gmail and Google Calendar through `gog`, Nextcloud calendar and tasks, a browser signed into the owner's Google account, and the laptop (`ssh omnibook`). MCP servers come only from ome's own config: every claude run passes `--strict-mcp-config` with ome's `--mcp-config`. Chat loads project settings only (`--setting-sources project`); a job loads none (`--setting-sources ""`) and no skills, and runs in a scratch folder outside the workspace, since auto mode lets every write inside its working folder through.
- The model is a child process behind the `Harness` interface: `claude -p` (stream-json) now, an any-model CLI (opencode) later. No provider SDK in the core.
- A job is `jobs/<name>.toml` plus a gate script that prints `{"wakeAgent": true|false, "message": ...}`; the model runs only on true, with the message after the prompt. Every run goes to the run log, and every failure writes an inbox item, which Web Push will carry to the phone.
- Initiative policy (`POLICY.md` in the workspace): reading, writing mail drafts and what the owner asks for directly run freely; what ome proposes on its own (calendar adds, tasks, starting a laptop session) is an approval card; sending, deleting and paying never run.
- Secrets live in `~/.config/ome/` (mode 600), never in the repo or the workspace.
- Names and paths follow ~/dotfiles/docs/app-contract.md: command `ome`, environment `OME_*`, config `~/.config/ome/`, state `~/.local/state/ome/`.
- Similar products are compared feature by feature on the docs site ome serves at `/docs` (`docs/`, built with Zensical): their facts are `landscape/products/<slug>.yaml`, and `landscape/generate.py` writes the pages (`landscape/README.md`). Entries describe what a product does with sources and never rank, as the owner asked. What ome borrows, and the check of whether any product now does all ome does, is `docs/landscape.md`. When a change adds or plans a feature, update `landscape/products/ome.yaml`, run `make docs`, and update the table and list in `docs/landscape.md`. If one product then does everything ome does that the owner uses (on a model they accept, self-hosted without a relay), tell the owner before building more: they may switch to it.
- No Telegram anywhere (#8).
