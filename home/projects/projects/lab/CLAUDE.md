# lab

Fly visual system and locomotion.

- Run `lab test` before you report work done; the pre-commit hook (`.githooks/`, on with `git config core.hooksPath .githooks`) runs it before each commit. `lab docs` builds the site and `lab deploy` pushes it; there is no Makefile. Each checkout has its own `lab`, which refuses to act on another checkout: in a worktree run its `.venv/bin/lab`.
- Paths live in `src/lab/connectome/config.py`, remote ids in `src/lab/connectome/fetch.py`, and network imports in `fetch.py`. `tests/test_boundaries.py` enforces those three.
- Data follows Cookiecutter Data Science (decision #107), plus `data/cache` for the slow steps' tables (decision #109): `data/external` holds data from third-party sources (every connectome and the maps joined onto them), `data/raw` the lab's own data as collected, `data/interim` tables made here, `data/cache` the precomputed tables of the slow steps (not a CCDS folder), `data/processed` final tables, and `reports/figures` generated figures. `fetch.py` is the only code that downloads, and only into `data/external`; figures saved from papers go in `config.PAPERS` by hand, and the lab's recordings go in `data/raw` as collected, never edited afterwards. Keep data nothing reads: third-party files in `data/external`, tables made here in `data/interim`.
- `data/external` and `data/raw` are links to one store, `/home/jaeho/projects/lab.wt/_data/external` and `.../raw`; `data/interim`, `data/cache` and `data/processed` belong to each checkout. A new worktree gets `mkdir data`, then `ln -s` of the two. Remove the store's files only through `fetch` or on request.
- In `load.py`, a `read_*` function returns a data file as shipped and a separate function makes the format the analysis uses (the marimo-research skill has the rule for notebooks). The older `load_*` functions do both and are being retired: new code calls a `read_*` function and its transform. A file under `config.EXTERNAL` keeps its source's name; one from a repository sits under `src/<repository>/` at its path there. Two exceptions, named by `fetch`: the census (`codex/cell_types.csv.gz`, because its product name is a remote id) and the CAVE pull (`cave/connections.parquet`).
- A new cell type needs no fetch: `config.CONNECTIONS` (`data/external/cave/connections.parquet`) holds the connections of every FlyWire proofread neuron. A notebook filters it with `load.load_connections_of`.
- Do not hand-edit what `docs/gen_site.py` writes (`docs/book.yml`, the home page). Book settings live in `SETTINGS` there. `lab docs` regenerates them.
- Search `gotcha` issues before you debug CAVE, fafbseg, or marimo.
- Paper notes live in Zotero.
- Keep an eye out for translational opportunities: when a result or a method could carry over to another field (robotics, sensor fusion, machine learning, a disease model, a tool other labs could reuse), say so when you see it.

## Notebooks

- Notebooks sit in folders by area and analysis (`notebooks/connectome/retinotopy/`): an analysis folder holds its main notebook, named for the folder, its data notebook `data.py`, and its children, and a child with children of its own gets a folder inside (decision #106). One notebook per question, and every notebook is a page of the lab's site, whose table of contents follows the folders. The site (lab.jaehho.com) is for the lab only, behind a Cloudflare Access login, so a notebook may embed figures from papers, credited under each; a figure saved from a paper goes in `config.PAPERS / "<Author Year>"`, named for its figure number. A figure is a function in `lab.connectome.plots` that its question notebook calls and saves to `config.FIGURES`.
- A new question starts as an exploration in `explorations/YYYY-MM-DD-<slug>/` (the marimo-research skill has the workflow). Its scripts read data through `config` and `load` as a notebook does and are held to `tests/test_boundaries.py`; they write tables to the folder's `out/`, which git ignores, and the figures its `README.md` shows to its `figures/`, which git keeps.
- `docs/gen_site.py` writes a symlink under `docs/content/notebooks/` for each notebook, at its path under `notebooks/`, so a new notebook needs nothing more.
- Each dataset in `load.DATASETS` names its `group`, the folder whose `data.py` shows it: the closest common parent of the notebooks that read it, which `tests/test_data_notebooks.py` checks. A question notebook's Data section links to those sections and rarely shows a raw table. `lab connectome status <group>` and `fetch <group>` cover a folder's datasets and those of the folders above it.
- A slow step (over about a minute) is a module's `cache_step`. `lab connectome cache <notebook>` runs it and writes its tables to `config.CACHE` (`data/cache`) at the notebook's path, and the notebook reads them with `cache.read_cache`. This cache is not marimo's `mo.persistent_cache` (`__marimo__/cache/` beside a notebook): a notebook cannot remake these tables itself and names the command that does. The step is named by its notebook's path under `notebooks/` in `STEPS` in `cli.py`. `lab connectome cache [<notebook>...]` (every step by default) runs a step only when it has no `run.json`, an input is missing, or its code, `uv.lock`, or an input's size, time or listing differs from what `run.json` records; `--force` runs the named steps, or all, regardless. It takes steps to be independent: it neither orders a step after one whose tables it reads nor runs steps in parallel. When steps come to depend on each other, put a build engine behind it (make, or Snakemake, DVC or doit, checked first for how each decides a step is stale) instead of adding ordering to it.
- A figure, table, or sentence names what it is about wherever the context is not on screen with it: titles, axis labels, legends and column names say `LC10a cell (right eye)` or `share of LC10a output to AOTU019`, not `cell` or `share`. A figure is often seen without the text around it.
- A diagram (a schematic of cells, partners, or a method's steps) is a manim still drawn with `lab.connectome.draw`.
- A question notebook opens with `# Title`, `## Introduction`, `### Question`, and the home page card shows the paragraph under `### Question`. A reference notebook such as `data.py` opens with `# Title` and a paragraph, which its card shows.
- `pyproject.toml` ignores `E501` in `notebooks/` (markdown cells are one line per paragraph), so keep code lines under 79 by hand or with `ruff format`. `W505` runs only under `src/`.
- Name another notebook in prose as a link whose path is relative to the linking notebook's folder, as the site resolves it: `` [`eye_map`](?file=eye_map.py) ``, `` [`data`](?file=../data.py#section) ``. `uv run python tools/link_notebooks.py --fix` rewrites bare names and warns about links to notebooks that no longer exist. Links may be cyclic.
- A notebook links to the notebook it belongs to: its folder's main notebook, or for a main notebook, the main notebook of the folder above (`tools/link_notebooks.py` checks it). A notebook still at the top of `notebooks/` keeps the older rule until it moves: a follow-up carries its parent's stem as a prefix and links to it.

## Package (`src/lab/connectome`)

- A function moves into the package when another current notebook or a slow step can use it. Otherwise it stays in its notebook. Code that one analysis folder alone uses goes in a subpackage that mirrors the folder (the marimo-research skill's closest-common-parent rule).
- Docstrings are numpydoc. Name no callers or notebooks (they go stale) and tell no project history (it goes in an issue).
- Every public function has an example: a doctest on a small input with generic names. pytest runs it (`--doctest-modules`), so the example is the function's test, and `lab docs` shows it in the API reference. A function that reads a file takes its path as an argument (default: the `config` path), and its example writes a toy file to a temp folder. A function that calls the network or needs the real `data/` is listed in its module's `__doctest_skip__` (`conftest.py` skips those doctests), and its example shows real output from a run. Its logic is tested in `tests/` with `monkeypatch`, not by extra arguments.
- A function that returns a figure (matplotlib, plotly, PNG bytes, or an HTML string) ends its example by binding it to `figure`, on an input that looks like data. `docs/api_figures.py` runs the example and embeds the result; it runs only examples that bind `figure`, so a `+SKIP` example that fetches is shown and never executed. Do not assert on the figure.
- `lab.connectome.strength.CLASSIFIERS` holds the ways to call a partner strong, all with one signature. `config.CLASSIFIER` names the one notebooks use.

## Notes

- A note names another note, a meeting summary, or a cell type that has a note with an Obsidian link, never a path in a code span: `[[connectomics]]` by filename, a path suffix only where the name is not unique, an alias for a date-stamped name (`[[2026-10-20-1014-lc-connectome-analysis-review|2026-10-20 meeting]]`). The vault is `~/Obsidian`, where `lab/` is a symlink to `notes/`.
- Link a type at its first mention in each heading section (the intro before the first heading is one) and not again in that section. Repeat the link in a table or a list that works as data. Do not link in a heading, a code span, a quotation, or frontmatter.
- A type with no note yet gets the same link once a notebook or a meeting talks about it: a dangling link is a note still to write. Other cell types stay plain text.
- Notes live in `notes/`, one subfolder per kind of thing (`connectomics/types/`, `connectomics/neuropils/`). A subfolder usually has a note named the same as itself (`types/types.md`) for what holds across its notes, and one note per item, named for it (a cell type by its Codex type). An item note is a `#` title, a line on what it is, and quotes inserted with `gz` in nvim (author, year, page, PDF and DOI links); personal communication is attributed by name. It has no frontmatter and no "See also" section; the first-mention links carry the edges.
